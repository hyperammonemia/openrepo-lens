本次观察

同样设置 200 条上限，并不意味着获得相同长度的时间记录。django/django、fastapi/fastapi、encode/starlette 的样本未覆盖完整 90 天，因此不能把样本内记录数解释成整个窗口的新增总量。

Django 样本里只有 PR，不能计算 Issue 关闭比例。工作台将其显示为缺少样本；零 Issue 也不能推导为零问题。

关闭比例与已关闭耗时描述的是采集到的记录。没有纳入未关闭记录的最终耗时，也没有核验关闭原因，因此不据此评选“维护最好”的框架。

实现与证据

Python 标准库负责采集、去重和指标计算，HTML/CSS/JavaScript 负责离线展示。每个原始响应保留 SHA256、请求 URL 和读取时间。离线重建可以与现有分析文件对照，页面无需安装依赖。

自动验证结果见 validation.json；原始数据清单见 manifest.json。截图用于记录桌面与移动端展示效果。

方法边界

  • 这是按最新创建记录截取的描述性样本，不能当作仓库全部历史、全部积压或随机样本。不同仓库覆盖的日期不同。
  • 30 天和 90 天筛选仅作用于已采集记录；当样本最早日期晚于窗口起点时，该窗口覆盖不完整。
  • 关闭比例是样本 Issue 的当前关闭状态比例。关闭可能代表重复、拒绝或其他处理，并不等于问题已修复。
  • 关闭耗时中位数仅统计有有效关闭时间的已关闭 Issue，排除尚未关闭记录，不能代表整体解决速度。
  • API 顺序读取期间数据可能变化；创建时间晚于采集起点的记录被排除，当前状态不代表采集起点的历史状态。
  • 部分项目在其他平台管理问题，或停用 GitHub Issues。零条 Issue 不能解释为零问题或维护更好。
  • 发布信息取 GitHub releases 列表的首条；无记录不代表没有软件版本发布。仓库推送时间也不等同于代码质量。
  • 这些观察不能直接用于安全、质量或维护风险排名；项目选择及样本上限会影响结果。

接口依据

GitHub Issues 接口定义 Issue 与 PR 的区分字段；分页说明解释如何识别下一页；限流说明列出匿名请求的配额。
